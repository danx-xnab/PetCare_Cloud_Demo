# 汇报要点

## LLM 使用方式

- 用 LLM 解析用户自然语言记录，输出固定 JSON。
- 后端不直接相信自由文本，而是要求字段包含 `pet_name`、`record_type`、`summary`、`symptoms`、`severity`、`need_reminder`、`reminder` 和 `reply`。
- JSON 被写入聊天消息表，同时派生健康日志和提醒任务。
- 如果没有 API Key，demo 使用规则解析器兜底，保证演示稳定。

## 模型能力分析

- 优势：能从口语化输入中抽取宠物、症状、时间和提醒意图，降低用户填写表单的成本。
- 风险：宠物健康相关内容不能替代兽医诊断；模型输出可能漏字段或误判时间。
- 工程控制：使用固定 JSON Schema、后端二次校验、失败时走规则解析、严重症状只做风险提示和观察提醒。

## 课堂演示重点

- 先展示多宠物档案，说明传统 CRUD 的基础能力。
- 再展示聊天式输入，突出 LLM 把自然语言转为结构化业务数据。
- 最后展示云架构页，说明 ECS、对象存储、数据库、消息队列和云函数的作用。
